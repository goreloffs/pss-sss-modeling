# PSS/SSS Generator & Detector (3GPP LTE)

Учебный проект на Python для моделирования первичного (PSS) и вторичного (SSS) сигналов синхронизации в нисходящем канале LTE (3GPP TS 36.211, разделы 6.11.1 и 6.11.2).

Проект демонстрирует генерацию сигналов, их свойства корреляции, устойчивость к шуму и фазовым сдвигам, а также работу приёмника с оценкой и коррекцией частотного сдвига.

## ▶️ Запуск

```bash
python pss_sss.py
```

После запуска скрипт:
1. Сгенерирует PSS и SSS для заданных `N_ID_1` и `N_ID_2`.
2. Отобразит серию графиков в отдельных окнах.
3. Выведет в консоль результаты обнаружения PSS и оценки частотного сдвига.

В блоке `if __name__ == "__main__":` можно изменить:

```python

N_ID_1 = 10      # Идентификатор группы (0...167)
SNR_dB = 20      # Отношение сигнал/шум (дБ)
```

Параметры приёмника:

```python
freq_offset_true = 500   # Истинный частотный сдвиг (Гц)
sample_rate = 30.72e6    # Частота дискретизации (Гц)
```

## 🧩 Описание модулей

### 1. Генерация PSS

```python
generate_pss(N_ID_2)
```

Реализует формулу 3GPP 36.211 (6.11.1) для последовательности Zadoff-Chu длиной 62:

- `N_ID_2 = 0` → корневой индекс `u = 25`
- `N_ID_2 = 1` → `u = 29`
- `N_ID_2 = 2` → `u = 34`

Возвращает массив из 62 комплексных отсчётов.

### 2. Генерация SSS

```python
generate_sss(N_ID_1, N_ID_2)
```

Реализует формулу 3GPP 36.211 (6.11.2):

- Вычисляет индексы `m0`, `m1` на основе `N_ID_1`
- Формирует m-последовательности `s̃`, `c̃`, `z̃` через сдвиговые регистры
- Формирует чётные и нечётные поднесущие, чередует их

Возвращает массив из 62 символов.

### 3. Вспомогательные функции

| Функция | Назначение |
|---|---|
| `cross_correlate(x, y)` | Кросс-корреляция сигналов (через `scipy.signal.correlate`) |
| `add_awgn(signal, snr_db)` | Добавление AWGN с заданным SNR |
| `pss_detector(received_signal, pss_candidates)` | Поиск `N_ID_2` по максимуму корреляции |
| `frequency_offset_estimation(...)` | Оценка частотного сдвига по фазе корреляции |
| `correct_frequency_offset(...)` | Компенсация частотного сдвига |
| `plot_resource_grid(pss, sss, bandwidth_rb)` | Визуализация ресурсной сетки |

## 📊 Графики и результаты

Скрипт строит шесть групп графиков:

1. **Созвездия PSS и SSS** — визуализация комплексных символов.
2. **Кросс-корреляция PSS** — сравнение автокорреляции и взаимной корреляции (низкий уровень боковых лепестков).
3. **Устойчивость к фазовому сдвигу** — амплитуда корреляции не зависит от сдвига, а фаза — зависит.
4. **Помехоустойчивость** — созвездие и корреляция при добавлении AWGN.
5. **Частотная коррекция** — сравнение реальной части и фазы сигнала до/после компенсации.
6. **Ресурсная сетка и три PSS** — расположение сигналов в сетке 6 RB и три варианта PSS.

Пример вывода в консоль:

```
Сгенерирован PSS (N_ID_2=0) длиной 62
Сгенерирован SSS (N_ID_1=10, N_ID_2=0) длиной 62

--- Моделирование приемника ---
Обнаружен N_ID_2 = 0 (истинное значение 0)
Истинный частотный сдвиг: 500 Гц
Оцененный частотный сдвиг: 502.3 Гц
```

## 📚 Теоретическая справка

### PSS (Primary Synchronization Signal)

- Генерируется из последовательности **Zadoff-Chu** длиной 63 (используются 62 центральных элемента).
- Занимает **62 поднесущие** в центре полосы.
- Передаётся в **последнем OFDM-символе** слота 0 и слота 10 (FDD).
- Используется для:
  - первичной синхронизации,
  - определения `N_ID_2` (0, 1, 2),
  - оценки частотного сдвига.

### SSS (Secondary Synchronization Signal)

- Основан на **m-последовательностях**.
- Занимает **62 поднесущие** в предпоследнем символе слота 0 и слота 10 (FDD).
- Позволяет определить `N_ID_1` (0…167).
- Полный **PCI** (Physical Cell ID) вычисляется как:

  ```
  PCI = 3 * N_ID_1 + N_ID_2
  ```

### Частотная синхронизация

Фазовый набег между переданным и принятым PSS:

```
φ = 2π · Δf · T
```

где `T` — длительность корреляционного окна. Отсюда:

```
Δf = φ / (2π · T)
```
